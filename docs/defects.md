# Четыре дефекта части A: причина → исправление → доказательство

## 1. Общий run для разных моделей

**Симптом.** Все шесть конфигураций писали params, метрики и модель в один
дочерний run `all-candidates`. Повторные `log_params` с другими значениями
MLflow запрещает, поэтому в коде стояла «заплатка»
`if not ...data.params:` — параметры логировались только у первого кандидата,
а `val_loss`, `samples.json` и `model/` следующих кандидатов перезаписывали
предыдущие. Сравнить конфигурации и зарегистрировать конкретную было нельзя.

**Исправление** (`src/sweep.py`). Каждый кандидат открывает свой вложенный run
`mlflow.start_run(run_name=candidate["name"], nested=True)` внутри
родительского `sweep`; заплатка с условием удалена, params логируются всегда.

**Доказательство.** В MLflow у run `sweep` шесть дочерних runs с собственными
`r`, `lr`, `target_modules`, кривыми и `model/`. `make check`:
`PASS 1. Минимум шесть отдельных законченных runs`,
`PASS 3. Конфигурации и кривые соответствуют бюджету`,
`PASS 4. Реальный адаптер ... совпадает с логом`.

## 2. Потеря файлов после замены контейнера

**Симптом.** Метаданные runs хранились в Postgres (volume `postgres`), а файлы
артефактов — в `/mlartifacts` внутри контейнера `mlflow`. Volume `artifacts`
был объявлен, но не подключён к сервису. После `docker compose up --force-recreate`
записи runs оставались, а `model/`, `samples.json` и probe-файл исчезали.

**Исправление** (`compose.yaml`). У сервиса `mlflow` подключён именованный volume:
`volumes: - artifacts:/mlartifacts`.

**Доказательство.** `make check-storage` пишет probe-файл, пересоздаёт только
контейнер `mlflow` и скачивает файл обратно: SHA256 совпадает
(`metrics/storage-check.json`). `make check`: `PASS 8. Артефакт пережил
пересоздание контейнера`.

## 3. Нет версий train/val

**Симптом.** `provenance()` считал `data_train_sha256` и `data_val_sha256`, но
`src/sweep.py` отбрасывал их фильтром `if not k.startswith("data_")`. По run
нельзя было доказать, на каких тензорах обучалась модель, а `select()` в
`promote.py` отказывал «отсутствует или устарел data_train_sha256».

**Исправление** (`src/sweep.py`). В теги runs идёт весь `provenance(p)`:
git sha, флаг dirty, хеш кода, конфига и обоих файлов данных. Сами тензоры и
исходный `train.jsonl` версионируются DVC (`data/**/*.dvc`, `dvc.lock`).

**Доказательство.** У каждого кандидата есть теги `data_train_sha256`,
`data_val_sha256`, `code_sha256`, `config_sha256`, `git_sha`, `base_revision`.
`make check`: `PASS 2. Код, данные, конфиг и база имеют версии`.

## 4. Обход порога по loss

**Симптом.** `promote()` только вычислял отношение `final/base` и сразу
регистрировал модель с тегом `validation=passed`. Функция `gate()` с порогом
`max_val_ratio` нигде не вызывалась, поэтому в реестр (и под alias) попадал
кандидат с любым loss, включая NaN.

**Исправление** (`src/promote.py`). Первой строкой `promote()` вызывается
`ratio = gate(run, threshold)`; при непройденном пороге, NaN или незавершённом
run бросается `ValueError` до `register_model` — реестр не меняется.

**Доказательство.** `make check`: `PASS 6. Запрет регистрации при непройденном
пороге` — с порогом 0.0 лучший кандидат не регистрируется, временная модель
в реестре не создаётся. `make candidate` регистрирует версию только после
прохождения порога `max_val_ratio: 1.0`.

## Дополнительно: переносимость на Windows (не входит в четыре дефекта)

Первый полный прогон на Windows дал `make check` 7/9; оба провала —
особенности платформы, а не логики:

- **Проверка 4.** MLflow 2.22 записывает путь артефакта модели через
  `os.path.join`, на Windows это `artifacts\adapter`. Сервер не отдаёт такой
  путь по HTTP (`%5C` → 500). Исправление: `posix_artifact_paths()` в
  `src/sweep.py` после `log_model` перезаписывает `model/MLmodel` с
  `artifacts/adapter`.
- **Проверка 7.** Тест запускает `src/predict.py` через `python -I`, а этот
  режим игнорирует `PYTHONUTF8`: вывод уходил в cp1251, и `manifest.json`
  читался в cp1251. Исправление: `predict.py` переключает stdout/stderr на
  UTF-8, `model.py` и `common.py` читают/пишут файлы явно в UTF-8.
- Весь репозиторий хранится с LF (`.gitattributes`), чтобы хеши кода и
  отпечаток `tests/` не зависели от `core.autocrlf`.

Код обучения изменился, поэтому sweep, регистрация кандидата и оценка
пересобраны заново целиком; первый (неполный) sweep остался в MLflow
как история, в отчётах используется только новый.
